Overview

P-Sphere is a self-hosted photo library. It does what a cloud photo service does (backup, albums, search) without your photos going to anyone else's servers.

It works at two levels:

  • Nearby sync. The Android app copies photos directly between phones on the same Wi-Fi. No account, server or internet connection is involved.
  • Your own server (optional). A Node.js server you run at home keeps a permanent copy of your library and adds a web app, smart albums, face grouping and natural-language search through a local LLM.

P-Sphere is alpha software. Keep an independent backup of photos you can't afford to lose until there's a stable release.

Quick start

Back up one phone to another in about five minutes.

  1. Install the app on both phones from the download page.
  2. Open P-Sphere on each phone, allow access to photos, and choose Start with nearby sync.
  3. On each phone, go to Settings → Backup → Choose folder and pick the folder to back up, usually DCIM/Camera.
  4. Connect both phones to the same Wi-Fi network. Each phone's Nearby phones card should list the other within a few seconds.
  5. Tap Sync now. When the card turns green, each phone has the other's photos in Pictures/PSphere Backup.

After that, P-Sphere syncs on its own every 6 hours on Wi-Fi. You can change this in Settings.

Install the app

The app isn't on Google Play yet. Download the APK from GitHub Releases and open it on the phone. Android asks you to allow installs from your browser or file manager the first time. The install guide has each step.

To build the APK yourself, install JDK 17 and the Android SDK, then run:

cd mobile
./gradlew assembleDebug        # app/build/outputs/apk/debug/app-debug.apk
./gradlew testDebugUnitTest    # runs the sync protocol tests

The Sync screen

The first tab shows everything about backup on one screen:

  • Status card. Shows whether this phone is up to date, syncing (with a file count), finished, or stopped with an error, with Sync now or Try again. If some phones synced and others didn't, it lists which.
  • Backup folder. The folder being shared and where other phones save it. Tap it to change.
  • Nearby phones. Phones running P-Sphere on this Wi-Fi. Search again clears the list and looks again, which helps after switching networks.

Pull down on the screen to search for phones again. Pulling down doesn't start a sync.

Backup folder

Only the folder you pick is shared, including its subfolders. Until you pick one, this phone shares nothing but can still receive photos from others.

  • Only photos and videos are sent: JPEG, PNG, HEIC/HEIF, WebP, GIF, BMP, DNG, MP4, MOV, 3GP, MKV, WebM, M4V and AVI.
  • Hidden folders such as .thumbnails and .trashed-* files are skipped.
  • Files are matched by content (SHA-256), so renaming or moving a photo doesn't send it again.

Where received photos go

Photos from another phone are saved to Pictures/<folder name>. The sending phone chooses the folder name in Settings → Backup → Folder name on other phones; the default is PSphere Backup. Giving each phone its own name (for example “Ravi's phone”) keeps their photos apart.

Received photos are added to Android's media index straight away, so they appear in Google Photos and other gallery apps. If a different file with the same name already exists, P-Sphere keeps both and adds a short code to the new name.

Received photos also count as “owned” for later syncs, so they're never sent back and forth. With three phones, a photo reaches the third phone through whichever phone it meets first.

Free up space

After a sync, Settings → Storage lists files from this phone that are now confirmed on another phone, and offers to delete the local copies.

Android 11 and later only let an app delete photos it created. P-Sphere can always remove photos it received, but your own camera photos may need deleting from your Gallery app. Settings tells you how many files it actually deleted.

Albums and search

The Albums and Search tabs appear once the phone is connected to your server (Settings → Server → Connect to a PSphere server).

  • Albums shows albums from the server. The sparkle button asks the server to build smart albums for trips, people, pets and places.
  • Search takes a plain description such as “beach sunsets 2024”. The server's local LLM ranks matching photos. If the LLM is offline, results fall back to keyword matching and are labelled Keyword match.

Signing out of the server switches the phone back to nearby sync. Photos already on the server stay there.

How phones find each other

Each phone runs a small TCP server on a random port and advertises it with DNS-SD (mDNS) as service type _psphere._tcp. The service name is PSphere-<model>-<id>, where id is six random characters created at install, so two phones of the same model don't collide. A TXT record carries the readable phone name and protocol version.

P-Sphere holds a Wi-Fi multicast lock while it runs, because some phones drop mDNS traffic without one. When Wi-Fi disconnects or reconnects, it clears the phone list and advertises and searches again.

Transfer protocol

A sync session runs over one TCP connection. Messages are newline-delimited UTF-8 JSON; file contents follow their FILE header as raw bytes.

client → HELLO {v: 2, deviceId, name, folder, hashes: [...]}
server ← HELLO {v: 2, deviceId, name, folder, hashes: [...]}
client → NEED  {hashes}          # files the client wants
server ← NEED  {hashes}          # files the server wants
server → FILE  {hash, name, size} + bytes   … repeated
client ← ACK   {hash, ok, reason?}
server → END
client → FILE … / server ← ACK …           # the other direction
client → END
client → BYE / server ← BYE
  • Each phase ends with END. A file deleted mid-sync is skipped instead of stalling the session.
  • Receivers verify every file. Bytes are hashed while they arrive. A file whose SHA-256 doesn't match is discarded and the sender gets ok: false.
  • Only requested files are accepted. Anything not in the receiver's NEED list is drained and refused.
  • Downloads are written to a hidden .part file and renamed when complete, so a dropped connection never leaves a half-written photo.
  • Concurrent sessions are deduplicated. If two phones offer the same photo at once, it's downloaded once.
  • Version mismatch. A phone on protocol 1 is refused with “running an older version of PSphere”.

Timeouts: 5 seconds to connect (with one retry), 30 seconds with no data before a session is abandoned.

Security model

Nearby sync is designed for networks you control. Be aware of what it does and doesn't do in this alpha:

  • Connections are never exposed to the internet; the server listens only on the local network.
  • File names and folder names sent by a peer are sanitised, so a peer can't write outside Pictures/<folder>.
  • There's no pairing. Any phone running P-Sphere on the same Wi-Fi can request your shared folder.
  • Transfers aren't encrypted. Someone on the same network could observe them.

Recommendation: use nearby sync on your home network. Avoid public, office or hotel Wi-Fi until pairing and encryption arrive.

Vision worker

The vision worker detects and groups faces and tags objects. It's optional; everything else works without it.

cd vision-worker
cp .env.example .env     # same DB_* and REDIS_* values as the core server
npm install
npm run build && npm start

Put the ONNX models in vision-worker/models/:

models/
├── face_detection.onnx    # e.g. a YOLOv8-face model
├── face_embedding.onnx    # e.g. ArcFace, 512-dimension output
└── object_tagging.onnx    # e.g. MobileNetV3 trained on ImageNet

Web app

cd web
npm install
npm run build            # output in web/dist/

Serve web/dist with nginx and proxy API calls to the Core server:

server {
    listen 80;
    server_name psphere.local;
    root /opt/psphere/web/dist;
    index index.html;

    location / {
        try_files $uri $uri/ /index.html;
    }
    location /api/ {
        proxy_pass http://localhost:3000;
        proxy_set_header Host $host;
        client_max_body_size 0;   # allow large video uploads
    }
}

Run as a service

Create /etc/systemd/system/psphere-core.service:

[Unit]
Description=PSphere Core API
After=network.target postgresql.service redis.service

[Service]
Type=simple
User=psphere
WorkingDirectory=/opt/psphere/core
EnvironmentFile=/opt/psphere/core/.env
ExecStart=/usr/bin/node dist/index.js
Restart=on-failure
RestartSec=5

[Install]
WantedBy=multi-user.target

Create psphere-vision.service the same way for the vision worker, then enable both:

sudo systemctl daemon-reload
sudo systemctl enable --now psphere-core psphere-vision

If you prefer PM2: pm2 start core/dist/index.js --name psphere-core, then pm2 save and pm2 startup.

Connect the app

  1. On the phone, open Settings → Server → Connect to a PSphere server, or expand Connect to a PSphere server on the setup screen.
  2. Enter the server's LAN address, for example http://192.168.1.100:3000. Don't use localhost; that means the phone itself.
  3. Choose Log in or Create account, enter your email and password, and name the device.

Uploads to the server run alongside nearby sync, using the same backup folder and schedule.

Production checklist

  • JWT_SECRET is a long random string and NODE_ENV=production.
  • PostgreSQL and Redis listen only on localhost or your LAN; ports 5432 and 6379 are firewalled from outside.
  • The Core server sits behind nginx, with HTTPS if it's reachable beyond your home network.
  • CORS_ORIGIN is set to the web app's exact address.
  • DATA_ROOT is on a disk with room to grow, and both it and the database are backed up.
  • systemd or PM2 restarts the services after a crash or reboot.

Troubleshooting

Phones don't see each other

  • Check both phones are on the same Wi-Fi network, not one on 2.4 GHz guest Wi-Fi and one on the main network.
  • Open P-Sphere on both phones and tap Search again.
  • Guest, office and public networks often block mDNS or stop devices from seeing each other (“client isolation”). Try a home router or a phone hotspot.
  • Turn off VPN apps; many route local traffic away from Wi-Fi.

“Couldn't reach <phone>”

The phone was found but didn't answer. Open P-Sphere on it (some phone makers stop background apps aggressively) and try again. If it keeps happening, exclude P-Sphere from battery optimisation on that phone.

“<phone> is running an older version of PSphere”

Update the app on every phone. Version 1.1 and later can't sync with 1.0.

Sync is stuck on “Waiting for Wi-Fi”

“Wi-Fi only” is on and the phone is on mobile data, or the battery is low. Connect to Wi-Fi, or turn “Wi-Fi only” off in Settings.

The app can't reach my server

  • Use the server's LAN IP (http://192.168.x.x:3000), not localhost.
  • Open http://<server-ip>:3000/api/health in the phone's browser. If it doesn't load, check the server's firewall.

Server: connect ECONNREFUSED ::1:5432

PostgreSQL isn't running or listens on a different address. Check sudo systemctl status postgresql and DB_HOST in .env.

Server: thumbnails aren't generated

sharp needs native binaries for your platform. Run npm rebuild sharp in core/.

Search always says “Keyword match”

The LLM isn't reachable. Check curl http://localhost:11434/api/tags for Ollama, and that LLM_MODEL matches a model in ollama list.

FAQ

Does P-Sphere work without internet?

Yes. Nearby sync only needs a local Wi-Fi network; it doesn't matter whether that network is connected to the internet.

Do I need an account?

Not for nearby sync. If you run a server, you create an account on your server. There's no central P-Sphere account.

Can several people share one server?

Yes. Each account on the server has its own separate library. Shared albums between accounts aren't available yet.

Does it back up videos?

Yes, common video formats are included. Large videos take a while on the first sync.

Will deleting a photo on one phone delete it on the others?

No. Sync only adds missing files; it never deletes anything on another phone.

How do I report a bug?

Open an issue on GitHub with your Android version, the app version (Settings → About) and what happened.

Privacy

The app has no analytics, crash reporting or advertising SDKs, and doesn't contact any server run by the P-Sphere authors. Nearby sync stays on your local network. When you use your own server, photos go only to the address you enter. AI features run on that server through the LLM you configure.
